# On-Page SEO Checklist — Renovo Studio

The single source of truth for on-page SEO on this site. Every page must pass every item that applies to its type.

**Read this before writing or editing any page. Check every page against it before shipping.**
`python3 tools/seo_check.py` checks the ⚙ items automatically; the rest are checked by reading the page.

> This checklist works for any site. To reuse it elsewhere, change the bits in **Site settings** below and swap the page types, file paths and reference files for that site's own. The rules themselves don't change.

## 1. Head / metadata (all pages)

- [ ] ⚙ **Title** 50–60 characters, primary keyword first, ` | Renovo Studio` at the end (so the keyword part gets about 44). Drop the suffix if the keyword needs the room.
- [ ] ⚙ **Meta description** 140–160 characters: keyword + the outcome + a soft CTA ("Book 15 minutes…"). Unique per page.
- [ ] ⚙ **Canonical**: absolute URL on the live domain, self-referencing, no trailing slash (home is the bare domain)
- [ ] ⚙ **Open Graph**: `og:title`, `og:description`, `og:image`, `og:url`, `og:type` (`article` for posts and case studies)
- [ ] ⚙ **Twitter Card**: `summary_large_image`
- [ ] ⚙ **`lang="en-US"`**, charset, viewport (the site uses US spelling)
- [ ] **Favicon** + `apple-touch-icon`
- [ ] **No `noindex`** on anything meant to rank (thank-you and legal pages may be noindex)

## 2. URL structure

- [ ] ⚙ **Lowercase, hyphens only**
- [ ] **Keyword in the slug**, under 60 characters, no dates, no stop words unless needed
- [ ] **Existing URLs never change** without a 301 redirect in the host's config (`_redirects`, `vercel.json` or `.htaccess`, whichever host the site ends up on)

## 3. Headings

- [ ] ⚙ **Exactly one H1**, containing the primary keyword
- [ ] ⚙ **No skipped levels** (footer column headings count)
- [ ] **H2s use secondary keywords and real buyer questions**, written for a founder skimming, not for a crawler

## 4. Body copy

- [ ] **Primary keyword in the first 100 words**
- [ ] **Direct answer first**: 40–60 words that answer the search on their own
- [ ] **Length:** blog posts 800–1,400 words (articles ≤ 1,800). Homepage ≤ 450 words, single service pages ≤ 400, services hub ≤ 300 once individual service pages exist, landing pages 700–1,000
- [ ] **Short paragraphs** (1–4 sentences), grade 8–10, active voice, **"we"**
- [ ] **Real proof inline**: at least one number from `content-guide/stats.md` or the case study JSON, with where it came from ("across client campaigns", "for one SaaS client")
- [ ] **"Here's what we'd fix first"**: every blog post leaves the reader one thing they could do this week without hiring anyone. On the homepage and service pages it lives in the closing CTA ("we'll tell you what we'd fix first")
- [ ] **Voice files applied**: passes "Tells that it's AI-written" in `content-guide/voice.md`, and the humour rules in `content-guide/humour.md`

## 5. FAQ

- [ ] **Real questions** (People Also Ask + what prospects actually ask on calls): 4–5 on blog posts and landing pages, **3 on single service pages** (≤ 30 words each). None on the homepage.
- [ ] **2–4 sentence answers**, first sentence answers alone
- [ ] ⚙ **FAQPage JSON-LD** matching the visible text exactly

## 6. Images

- [ ] ⚙ **Alt text on every image** (decorative → `alt=""`); project images describe what's shown ("Med spa CRM logo on a teal background")
- [ ] ⚙ **`width` + `height` on every image** (`tools/seo.py` adds them from the file)
- [ ] **Descriptive filenames**, e.g. `med-spa-booking-funnel.webp`
- [ ] **WebP**, content images under 150 KB, hero under 200 KB
- [ ] **Hero not lazy** (`fetchpriority="high"`); everything below the fold `loading="lazy"`
- [ ] **Real screenshots before stock.** Stock only where no real image exists
- [ ] **OG image** 1200×630 per page (falls back to `assets/img/og-default.png`; case studies use their cover)

## 7. Internal links

- [ ] **Blog posts: 3–5 internal links**, at least **one to the matching service** and one to a relevant case study
- [ ] **Services: link to 2–3 case studies per service**, plus related posts once they exist
- [ ] **Industry pages: link to the case study from that industry** and the services used
- [ ] **Case studies: link to the services used** and to the booking page
- [ ] **Descriptive anchors**, never "click here" / "read more"
- [ ] ⚙ **Breadcrumbs on every page except home** (visible + `BreadcrumbList`)
- [ ] **No orphan pages**: every page is linked from the nav, the work grid or another page, and listed in `sitemap.xml`

## 8. External links

- [ ] **Blog posts: 2–3 authoritative sources** (Google Search Central, Google's sender guidelines, platform docs, original research), never another agency's blog
- [ ] **Every link opened and checked** before publishing
- [ ] ⚙ **`target="_blank"` always with `rel="noopener"`**
- [ ] **No links to matthewrissik.com** unless the owner asks for them

## 9. Schema (JSON-LD)

Generated by `tools/seo.py` (site-wide + page types) and `tools/build_case_studies.py` (case studies). Never hand-typed.

| Schema | Where |
|--------|-------|
| `Organization` (Renovo Studio, founder = Matthew Rissik `Person`) + `WebSite` | site-wide |
| `Service` | services hub, service and industry pages |
| `BlogPosting` (author = Matthew Rissik, publisher = Renovo Studio) | blog posts |
| `Article` | case studies |
| `BreadcrumbList` | every page except home |
| `FAQPage` | any page with a visible FAQ |

- [ ] ⚙ **Every block parses**
- [ ] **Passes Google's Rich Results Test** (once the site is live)
- [ ] **Schema only describes what's visible**
- [ ] ⚙ **No `LocalBusiness`** (or subtypes like `ProfessionalService`). Renovo isn't a local business
- [ ] ⚙ **No `Review` / `AggregateRating`** for Renovo's own services from its own site

## 10. E-E-A-T

- [ ] **Byline** on every post: "Matthew Rissik, Founder, Renovo Studio"
- [ ] **Author card** at the end of every post: photo, one-line bio, LinkedIn link
- [ ] **Published + "Last updated" dates** visible, matching schema
- [ ] **Real proof**: numbers, client types and screenshots from `content-guide/` and the case study JSON only
- [ ] **About section** with the founder's real story, what we do and don't do, and socials (currently on the homepage; give it its own page when there's more to say)
- [ ] **Case studies on-site**, so the proof builds this domain's authority

## 11. Accessibility

- [ ] ⚙ **Landmarks**: `<header>`, `<nav>`, `<main>`, `<footer>`; `<article>` for posts and case studies
- [ ] ⚙ **Skip-to-content link** first in `<body>`
- [ ] **Contrast** ≥ 4.5:1 body, ≥ 3:1 large text
- [ ] **Visible focus rings**
- [ ] **Labels on every form field**
- [ ] ⚙ **No vague link text**
- [ ] ⚙ **Project filter buttons** are real `<button>`s with `aria-pressed`

## 12. Mobile

- [ ] Body text ≥ 16 px, tap targets ≥ 48 px, no horizontal scroll at 360 px, no popups on load

## 13. Conversion (home, services, case study pages)

- [ ] ⚙ **"Book a call" CTA above the fold** linking to `contact.html`
- [ ] **CTA repeated**: after proof, mid-page, end of page
- [ ] **"No pitch, no pressure" framing**: 15 minutes, what we'll look at, "whether or not you hire us"
- [ ] **Proof near every CTA**: a stat or case study card
- [ ] **Single service pages: what it is → who it's for (with one "not for" sentence) → what you get (max 5 bullets) → proof → 3 FAQs → book a call.** Nothing else
- [ ] **Format/pricing honesty**: fixed-scope vs retainer; an actual price only if it's in `stats.md`
- [ ] **Testimonials only if real** and in `stats.md`. None is better than invented

## 14. Industry pages (extra rules)

Same doorway-page risk as location pages. Google penalises the same page with the industry name swapped.

- [ ] **Only build one where there's a real project in that industry** (from the case study JSON or `stories.md`) **and** real search demand
- [ ] **50%+ of the copy unique to that industry**: how buyers in that industry search, their sales cycle, what the case study fixed, industry-specific objections
- [ ] **Features that industry's case study** with its real numbers

## 15. Long-form (1,500+ words)

- [ ] **Table of contents** linking to each H2, ⚙ **`id` on every H2**, **back-to-top** link

## How to use this file

1. Read it before writing or editing a page.
2. Add the page to `PAGES` in `tools/seo.py` (title, description, keyword, type, breadcrumb) and its keyword to `content-guide/keyword-log.md`.
3. Run `python3 tools/build_case_studies.py` (it re-applies `tools/seo.py`), then `python3 tools/seo_check.py`. ⚙ items fail the check if missing.
4. Read the page once against the rest, then ship.

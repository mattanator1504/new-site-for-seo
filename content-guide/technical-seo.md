# Technical SEO — Renovo Studio

Site-wide technical SEO. Re-check before every deploy.
On-page items (titles, headings, schema per page) live in `on-page-seo.md`.

**Target:** Lighthouse **100 / 100 / 100 / 100** (Performance, Accessibility, Best Practices, SEO) on desktop **and** mobile.

**Honest note on mobile Performance:** Lighthouse's mobile test simulates a slow phone on a slow network, and the score moves a few points between runs. Accessibility, Best Practices and SEO must be 100 on mobile too. Mobile Performance must be **≥ 95 on three runs in a row**; chase 100 but don't wreck the design for the last two points.

**Test in an incognito window** (or with extensions off). Browser extensions inject their own scripts, and Lighthouse counts them against the page (e.g. "unused JavaScript" from `chrome-extension://…` URLs).

> Reusable for any static site: swap the paths and the domain; the rules stay the same.

---

## 1. Build setup (static HTML, no framework)

Plain HTML/CSS/JS, deployed as static files on Vercel. Three scripts produce the final pages:

| Script | Does |
|--------|------|
| `tools/build_case_studies.py` | Case study pages, work grid, homepage cards, sitemap, then runs `tools/seo.py` |
| `tools/seo.py` | Titles, meta, canonical, Open Graph, `lang="en-US"`, site-wide JSON-LD, `width`/`height` on every image, then runs `tools/perf.py` |
| `tools/perf.py` | Inlines minified `assets/css/style.css` into every page, preloads the above-the-fold fonts, removes any Google Fonts requests |

**Always edit the sources** (`assets/css/style.css`, `PAGES` in `tools/seo.py`, `_source/case-studies.json`), then rebuild. Never hand-edit the generated `<head>` block or the inlined `<style>`.

Live domain: `SITE_URL` in `tools/seo.py` (currently `https://new-site-for-seo.vercel.app`). Change it when the real domain is connected, update `robots.txt`, rebuild.

## 2. Crawling and indexing

- [x] **`robots.txt`**: allow all, points at the sitemap
- [x] **`sitemap.xml`**: generated by the build. Every indexable page, `lastmod` set. No redirects, 404s or noindex pages in it
- [x] **Canonical on every page** (absolute, self-referencing)
- [ ] **`404.html`**: a real 404 page with links to services and contact (Vercel serves `404.html` automatically)
- [ ] **One domain version:** once the real domain is connected, `www` 301s to the chosen version (set in Vercel → Domains)
- [ ] **Old URLs redirect:** any URL that changes gets a 301 in `vercel.json` → `redirects`
- [ ] Thank-you and legal pages can be `noindex` and left out of the sitemap
- [x] **Preview deployments** get `X-Robots-Tag: noindex` from Vercel by default
- [x] **Internal files not deployed:** `.vercelignore` excludes `_source/` (contains `internalSourceNote`), `tools/`, `content-guide/` and the docs

## 3. Performance (Core Web Vitals)

Targets: **LCP < 2.5 s, CLS < 0.1, INP < 200 ms**, Total Blocking Time ≈ 0.

**Images** (the #1 cause of lost points)
- [x] **WebP**, sized to the largest they display at (logos ≤ 640 px wide, the Renovo wordmark 260 px)
- [x] `width` + `height` on every `<img>` (added by `tools/seo.py`)
- [x] Below-the-fold images `loading="lazy"`
- [ ] Any future hero image: **not lazy**, `fetchpriority="high"`, under 200 KB
- [x] No images used as text, no huge CSS background images

**Above the fold**
- [x] **Nothing above the fold starts invisible.** Scroll-reveal and split-letter animations are only used below the fold. A hidden hero heading or paragraph delays LCP by seconds

**Fonts**
- [x] **Self-hosted WOFF2** in `assets/fonts/` (latin subset), `font-display: swap`, no request to Google
- [x] **4 files total:** Anton 400, Barlow Condensed 600 + 700, Space Mono 400
- [x] **Preloaded:** Anton, Space Mono and Barlow Condensed 600 (all used above the fold; a late swap of any of them causes layout shift)

**JavaScript**
- [x] One small deferred script (`assets/js/main.js`), no libraries. Animations are CSS
- [x] The animation loop reads all sizes first, then writes styles (no forced reflow); element widths are cached
- [x] **No third-party scripts on page load.** If any are added later:
  | Script | Do this instead |
  |--------|-----------------|
  | Booking calendar embed | Only on `contact.html`, loaded on click ("Show available times") |
  | Form / chat widget | No chat widget. Forms post to an endpoint; no embed script on content pages |
  | Analytics | Load after the page has painted (`defer` + `requestIdleCallback`), or use a lightweight option (Plausible, Cloudflare Web Analytics, Vercel Analytics) |
  | YouTube embed | Thumbnail + play button that swaps in the iframe on click |
- [ ] Re-run Lighthouse after adding **any** script

**CSS**
- [x] One stylesheet, minified and inlined (no render-blocking request). No CSS frameworks or icon fonts from a CDN
- [x] Icons and illustrations as SVG

**Caching** (`vercel.json`)
- [x] Fonts: `public, max-age=31536000, immutable`
- [x] Images: 30 days + `stale-while-revalidate`
- [x] CSS/JS: 1 day + `stale-while-revalidate` (file names aren't fingerprinted, so not immutable)

## 4. Accessibility (must be 100)

- [x] Text contrast ≥ 4.5:1 (≥ 3:1 for large text). The scroll-lit manifesto uses a colour that passes, not low opacity
- [x] No `aria-label` on plain `<span>`/`<div>`. Split-letter headings carry a visually hidden copy of the text instead
- [x] Accessible names contain the visible text. Project preview buttons are a separate overlay `<span role="button">`, so the card's visible labels don't conflict with its name
- [x] Icon-only buttons have an `aria-label` (menu toggle)
- [x] Every form input has a `<label>`
- [x] No skipped heading levels (footer column headings are `h2`)
- [ ] Tap targets ≥ 48 px and not too close (check footer links on new pages)
- [x] `<html lang="en-US">`, skip link, `<main>`, no duplicate `id`s

## 5. Best Practices (must be 100)

- [x] HTTPS everywhere, no mixed content
- [x] **Zero console errors** on every page. A syntax error in `main.js` silently kills every animation and fails this, so run `node --check assets/js/main.js` after editing it
- [x] Images displayed at their real aspect ratio
- [x] No deprecated APIs, no `document.write`, no source maps shipped
- [x] Security headers (`vercel.json`): `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`, `Strict-Transport-Security`, `Permissions-Policy`

## 6. SEO category (must be 100)

- [x] Title and meta description present
- [x] Not blocked by `noindex` or `robots.txt`
- [x] Valid `robots.txt`
- [x] Descriptive, crawlable links (`<a href>`)
- [x] Images have alt
- [x] Valid canonical

## 7. How to test

```bash
python3 tools/build_case_studies.py      # rebuilds everything, re-applies SEO + performance passes
python3 tools/seo_check.py               # on-page ⚙ checks, must be 0 problems
node --check assets/js/main.js           # no syntax errors
npx serve . -l 3000                      # serve with compression (python's http.server doesn't gzip, which understates mobile scores)
npx lighthouse http://localhost:3000/ --preset=desktop --view
npx lighthouse http://localhost:3000/ --view          # mobile (default)
```

Test at least: home, services, work, blog, contact and one case study. They use different templates, so they fail differently.

After deploying, re-test the live URL on [PageSpeed Insights](https://pagespeed.web.dev/), in an incognito window.

## 8. After launch

- [ ] Google Search Console: verify (DNS TXT record is best)
- [ ] Submit `sitemap.xml`
- [ ] URL Inspection → Request indexing for home, services and the top case studies
- [ ] Bing Webmaster Tools: import from Search Console
- [ ] Check Search Console → Pages after 7 days: "Crawled – currently not indexed" usually needs more unique content or internal links

## 9. Moving to the real domain (one-time)

1. Connect the domain in Vercel, pick one version (with or without `www`) and 301 the other.
2. Set `SITE_URL` in `tools/seo.py` and the `Sitemap:` line in `robots.txt`, rebuild, deploy.
3. If an old site lived on that domain, inventory its URLs first and 301 every one that doesn't exist on this site (`vercel.json` → `redirects`).
4. Re-run section 7 on the live domain.
